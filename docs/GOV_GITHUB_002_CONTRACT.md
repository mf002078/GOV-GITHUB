## R01: commit-by-commit paths

The immutable legacy anchor is the exact source baseline above. CLI `--base`
must equal it; callers cannot skip a faulty intermediate commit by moving base.
Each subsequent commit must append both logs, use schema 2.0, and identify its
exact first parent in `baseline_sha`. Every newly appended entry in a commit
belongs to that revision. Their union of `code_files` must equal actual Git
changed paths, excluding **only** `worklog/CHANGELOG.jsonl` and
`worklog/CHANGELOG.md`. These two paths must not be listed as code_files.
All other paths, including workflows, checker, docs and assets, are included.

Rename detection is disabled: rename means deletion of the old path plus
addition of the new path, both listed. Binary and mode-only changes count as
path changes. Deleted paths must be listed. Paths use exact UTF-8 Git names;
non-UTF-8, newline, backslash or noncanonical paths fail closed. A log-only
correction may have empty code_files. No aggregate-diff shortcut: every commit
is checked, including transient changes later reverted. Merge commits are
rejected; integration/merge validation is a separate acceptance operation.

## R02/R05: immutable legacy and strict appendices

Both anchor files must be retained byte-for-byte. Anchor records alone use
LEGACY_COMPAT (their existing ID-presence contract); it cannot be extended to
new entries. Each revision also retains every byte of its first parent's logs.
New schema 2.0 entries use the existing field names and exact field set.
The Markdown appendix is generated by `render_entry(record)`: a heading plus a
canonical JSON fenced block, mirroring **all fields** exactly. This avoids
lossy free-text list/escaping conversions. Mismatches are rejected.

IDs are unique, timestamps are explicit UTC `Z` in chronological order,
version/summary/completed items/evidence references are required. Only a
CORRECTION may set correction_of, and it must reference an earlier entry.
Corrections to legacy IDs are new schema 2.0 records; no historical edits.
Empty code_files is permitted only when it matches actual non-log changes.

## R03: post-commit evidence; no self-referential SHA

A Git commit cannot embed its own SHA. Logs name the exact parent and the
repository-relative evidence artifacts. After committing, collect an external
JSON manifest (never amend the commit to insert its own SHA). Each candidate
revision requires one record with exactly these fields:

```json
{
  "schema_version": "1.0",
  "candidate_sha": "<exact 40 lowercase hexadecimal characters>",
  "provenance": "NOT_ATTESTED",
  "source_mode": "synthetic",
  "artifacts": [{"path": "<log evidence reference>", "sha256": "<64 lowercase hexadecimal characters>"}]
}
```

The outer manifest is an array. No missing/extra/duplicate revision or artifact
is accepted. Digests are compared to Git blob bytes at the exact commit, never
working-tree files, URLs or symlink targets. The checker performs no fetching.
Missing artifacts, wrong digests, stale SHA, arbitrary URLs, non-synthetic mode,
and claimed ATTESTED provenance fail closed. An unverifiable external origin
remains **NOT_ATTESTED**; successful structural validation never authenticates
the runner, actual execution, review, signer or artifact origin.

## Running checks

```sh
python -B -m unittest discover -s tests -v
```

For a clean committed checkout, produce a local **self-report** manifest:

```sh
python -B - <<'PY' > /tmp/gov-github-002-evidence.json
import hashlib, json
from tools.check_worklog import ROOT, blob, verify_commits
result = verify_commits()
print(json.dumps([
    dict(schema_version='1.0', candidate_sha=sha, provenance='NOT_ATTESTED',
         source_mode='synthetic', artifacts=[dict(path=p,
         sha256=hashlib.sha256(blob(ROOT, sha, p)).hexdigest()) for p in paths])
    for sha, paths in result['evidence_by_commit'].items()
], indent=2))
PY
python -B tools/check_worklog.py --evidence /tmp/gov-github-002-evidence.json
```

Missing manifest or dirty/untracked checkout blocks CLI verification. It only
checks committed snapshots. The pre-existing candidate CI invokes this checker
without a post-commit manifest and therefore **will fail closed** on these new
commits; no workflow or required check is weakened to hide that limitation.
The external evidence transport/CI integration still needs independent review.

`verify_legacy_fixture` supports the five original synthetic regression tests;
it is not an admission API and is not used by the production CLI.
